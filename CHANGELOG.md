# Changelog

All notable changes to Network Scope are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Firmware (SBOM) in the host details**: when an imported firmware SBOM matches the firmware a host reported (industrial identification, industrial traffic or LLDP-MED), the host details list its packages, with type, supplier, package URL, CPE name and licence on hover; single files are counted, not listed. Found as the CycloneDX export finds them (`sbom::for_hosts`).
- **VEX by package URL**: a CycloneDX statement that names its component by package URL (also as a BOM-Link into another document, `urn:cdx:...#pkg:maven/...`) keeps it and matches the components of firmware SBOMs by package URL (type, namespace, name; qualifiers ignored; the version in the statement's range).
- **Tested on real public files**: the 334 CISA advisories of 2026 (CSAF), the CycloneDX VEX guide's examples, and Syft 1.57.2 on the OpenWrt 25.12.6 root file system (CycloneDX 1.7 and SPDX 2.3) all import; the export with the OpenWrt SBOM nested passes the CycloneDX 1.6 schema. An ignored test takes such a file from `NS_REAL_SBOM`. A scan of 65,536 hosts exports in 4.5 s (86 MB; `docs/src/lab-and-testing.md`).
- **Desktop imports of SBOMs and VEX**: **File → Import firmware SBOMs…** and **Import VEX statements…** import files on the background worker and reload the caches, so the next export and the findings use them without a restart (VEX: the findings are worked out again at once). CVEs of SBOM components now carry KEV and EPSS data from the imported feeds.
- **Installed software over SNMP**: with SNMP credentials, the scan also reads `hrSWInstalledName` (HOST-RESOURCES-MIB) after every other table, up to 200 packages (100 in Safe Mode), stored sorted under one key, `snmp.software`, so a changed package is one change in a diff. Servers, some printers and appliances answer it; the CycloneDX export lists the packages as `application` components of the device. Tested with the built-in test agent only.
- **Upload to Dependency-Track** (`export ID --format cyclonedx --push URL --token-env VAR [--dt-project NAME] [--dt-version V]`): the CycloneDX document as a multipart `POST /api/v1/bom` with the API key in `X-Api-Key` (https:// only, except localhost); the project is created on the first upload and its BOM replaced on later ones. Not yet tried against a real server.
- **Vendor statements (VEX)** (`feeds import vex FILE|DIR...`, CSAF 2.0 or CycloneDX VEX). A finding whose CVE a statement covers for the product and version the scan saw carries it as `vex` (state, justification, detail, source). Not affected, fixed and false-positive findings stay listed but leave the risk score and the fix list, do not fail `findings --fail-on-findings`, and are greyed in the desktop with the vendor's reason on hover. The CycloneDX export writes the statement as the vulnerability's `analysis` and applies a firmware's statements to the CVEs of the libraries its SBOM lists. Fuzzed (`vex_import`); not yet tried with a real vendor document. `monitor` does not alert a new finding that a statement clears.
- **Firmware SBOM import** (`feeds import sbom FILE|DIR... [--sbom-vendor V] [--sbom-product P] [--sbom-version X]`). Reads CycloneDX (1.2 to 1.7) and SPDX (2.2, 2.3) JSON SBOMs from vendors or from firmware-image analysis (Syft, Trivy, EMBA) into `sboms.json`. The CycloneDX export nests a matching SBOM (same version, matching name, same vendor) under the firmware a device reported, with versions, package URLs, CPE names and licences, and with the NVD feed imported, the CVEs of those components point at the exact library. `feeds status` lists the SBOMs. Parsing is bounded (64 MB per file, 20,000 components, nesting depth 16) and fuzzed (`sbom_import`). Single files in an SBOM (Syft lists every file of an image) are counted in `network-scope:sbom-files-left-out`, not nested.
- **CycloneDX export of the network** (`export ID --format cyclonedx`, `scan --format cyclonedx`, and **File → Export → CycloneDX inventory** in the desktop). A CycloneDX 1.6 document with a `device` component per device, `firmware` components for what devices reported (S7, Modbus, EtherNet/IP, OPC UA, passive industrial traffic, LLDP-MED), `application` components for services that named their product (with the CPE name when known), and the CVEs of the findings as vulnerabilities pointing at the component they affect. Every value says where it came from; the rating is the finding's severity, not CVSS. On its own it is an inventory of what the network shows; imported firmware SBOMs (see the entry above) add what is inside the firmware. CI validates it against the official schema with `cyclonedx-cli` (pinned by SHA-256). Above 1,000 devices the file is written compact, and `network-scope:found-on` lists the first 100 addresses per vulnerability (`found-on-total` gives the count). Devices list the switch they hang off (LLDP over SNMP) as CycloneDX `dependencies` and `network-scope:connected-to` (address and port).
- **Windows code signing through SignPath Foundation** (free for open source). When the secret `SIGNPATH_API_TOKEN` is set, the release workflow uploads the executables and then the installer as artifacts, has SignPath sign them (origin verification, manual approval in SignPath), checks the signatures and adds SignPath's attribution to the release notes; Azure Artifact Signing stays as the alternative when only its secrets are set. The SignPath artifact configurations are in `.signpath/artifact-configurations/`, and the new [code signing policy](docs/src/code-signing-policy.md) page lists what is signed, the team roles and the privacy policy. Not yet used: the project still has to be accepted by SignPath Foundation.
- **Alert delivery tested against real receivers** (CI job `alert-receivers`, `lab/alert_receivers.sh`): a two-cycle `monitor` run delivers its alert to rsyslog over UDP and TCP and to nginx over HTTP and HTTPS (private CA via `SSL_CERT_FILE`); `lab/alert_receivers_check.py` compares what rsyslog parsed and what nginx received with the alerts, and checks that an HTTPS receiver whose certificate no trusted CA issued gets nothing and is reported as an unknown issuer. Passes on `ubuntu-latest` (rsyslog 8.2512.0, nginx 1.28.3).
- **Application icon and Windows file metadata.** A blue hexagon with a hub and the three devices it found, one of them amber for a finding (`assets/icon/`: `icon.svg`, a simplified `icon-small.svg` for 16 to 32 px, rendered to `network-scope.ico`, `icon-256.png` and `icon-48.png` by `build_icon.py`). A new `build.rs` (crate `winresource`, build-only, Windows targets) embeds it into `network-scope.exe` and `network-scope-cli.exe`. It also adds a version block (product and file version from `Cargo.toml`, shown in the file properties and Task Manager as "Network Scope") and an application manifest (`assets/windows.manifest`): run as invoker, Windows 10/11 compatibility, per-monitor DPI awareness, long paths, common controls 6. The desktop window uses the icon in its title bar and taskbar button instead of the egui logo (on Windows the 48 px render of the small-size design, which Windows scales down better than the 256 px one). The installer has the icon as its setup icon and as the icon of its entry in Installed apps, publisher, support and update links, and a version block of its own.
- **Taskbar identity on Windows**: the desktop window sets the AppUserModelID `Sparkz400.NetworkScope`, and the installer's Start menu and desktop shortcuts carry the same one, so a pinned shortcut and the running window share one taskbar button. On Linux the window's application ID is `network-scope`.
- **One window per user session on Windows**: starting the desktop app while it is already open restores (if minimized) and focuses the open window instead of opening a second one that would share its preferences and inventory. When the open window runs elevated and the new start does not, the new start opens normally. `--screenshot` runs are not affected.
- **The window remembers its size, position and maximized state** (preferences, `window`). A position whose title bar would be on no monitor any more (a disconnected screen) is ignored; outside Windows only the size and maximized state are restored. Checked on Windows: move and resize, restart, maximize, restart, and a saved off-screen position.
- **macOS app bundle**: releases add `network-scope-<version>-macos-arm64-app.zip` with `Network Scope.app` (`packaging/macos/make_app.sh`: `Info.plist`, the icon as `network-scope.icns` from `build_icon.py`, and a Local Network usage text). The release signs it with the hardened runtime, notarizes it with the binaries and staples the ticket; the macOS CI job assembles it, ad-hoc signs and verifies it and runs the bundled binary. Not yet tried on a Mac by hand.
- **Optional columns in the hosts table.** **Columns** next to the filters adds Manufacturer, Type, OS guess (sortable) and Risk, the worst finding of the host. Saved with the preferences.
- **Findings grouped by rule.** **Group by finding** on the Findings page shows one row per finding with the number of affected hosts; a click lists the hosts of that finding (**Show all findings** goes back). The flat view shows the host name next to each address.
- **Manual checks** (`docs/src/manual-checks.md`): what to try by hand on the Windows installer, the desktop in a real window and with a screen reader, and what should happen.
- **Click tests of the desktop.** `src/gui/uitest.rs` renders real frames of the window, finds widgets by their accessible names and clicks them: menus and submenus, the favorites menu, the preset picker with the Safe Mode question, row clicks and right clicks, the sidebar, grouped findings, the columns menu, dragging the details panel and scrolling a table sideways.
- **Help for one command** (`network-scope COMMAND --help`, `COMMAND -h`, `help COMMAND`): the usage lines of that command, the options that apply to it and two or three examples for the common commands (scan, monitor, findings, diff, export, history, changes, listen, feeds, devices, search, trace), cut out of the full help text. An unknown command is the usual error (status 1). The option descriptions are the general ones, so a few read as written for `scan` (`history --help` shows `--dry-run` with the scan wording).
- **zsh and fish completions** (`completions zsh`, `completions fish`; load with `source <(network-scope completions zsh)` after `compinit`, or `network-scope completions fish | source`). Generated from the same option tables as bash and PowerShell: commands as the first word, options after it, file names after options that take a file, the values of `--format`. Besides the tests on the generated text, CI loads both scripts in a real zsh and fish and asks them for a command and an option.
- **Progress for a plain `scan` on a terminal**: one line with the number of addresses and ports and whether Safe Mode is on, then `37/254 hosts done, 4 responded, 1:12 elapsed`, rewritten about every 2 seconds on stderr. Only when stderr is a terminal and none of `--quiet`, `--stream`, `--tui` is given, so redirected output and scripts see nothing new. The text is unit-tested, and the line was watched in a PowerShell terminal on Windows (it is rewritten in place).
- **MCP tools `changes`, `top_risks` and `list_alerts`** (read-only). `changes` answers what the CLI command does (`since`: `last`, a window such as `7d`, or a date); `top_risks` returns the network risk score, the riskiest hosts and the fix-first list of a scan (default: the newest completed scan); `list_alerts` returns the stored monitor alerts, newest first, with `limit` and `since`. Like the other query tools they never create or upgrade an inventory. Tested in process against a fixture inventory (output checked against the schemas; missing, older and write-protected inventories) and once over pipes; not yet with a real MCP client.
- **Delete on the Inventory page.** Every saved scan has a **Delete** button; a question names the scan (targets, date, hosts) before it is removed with its alerts. The row list shows the date of each scan, is laid out only for the rows in view, and shows a scan saved while the page is open at once.
- **Device details for devices seen only in passive traffic.** A row of Hosts by device that is not among the scanned hosts used to write "not in the active scan results" into the status line; it now opens a details panel with the MAC, manufacturer, type, names, addresses and what each protocol observed.
- **Copy from the tables.** A right click on a row of the Findings table or of Hosts by device copies the address, the finding, the CVE, the evidence, the MAC or the whole row.
- **Several rows can be marked** in the hosts table, the Findings table and Hosts by device: Ctrl+click adds or removes a row, Shift+click takes the rows from the one chosen last, and in the hosts table Shift with the arrow keys does the same (in the other two: Ctrl or Shift with Enter on a row's address). The menu of a marked row then starts with **Copy N addresses** and **Copy N rows** (tab-separated, one row per line). Marking does nothing else: there is no action on several hosts besides copying. Shift+click and the copy were tried in a real window on the hosts table.
- **Keyboard access to the Findings and device tables.** The address at the start of a row (the title in the grouped findings) is a control: Tab reaches it, Enter opens the host, as in the hosts table.
- **The desktop says when a scan ends, and asks before it quits one.** The taskbar button flashes when a scan the user started ends while the window is not in front. Closing the window (or `Ctrl+Q`) during a scan or capture asks **Quit while a scan is running?** first. Tried in a real window on Windows 11: the question appears and **Keep running** continues the scan; the taskbar button shows the attention mark when a scan ends while the window is minimized. **Stop and quit** was not clicked there.
- **Files can be dropped on the window**: an address list fills the Addresses field (no scan starts), a capture is read for OT assets, anything else is named in a message.
- **Interface addresses are filled in** on the Passive / OT page (Windows): choosing an interface fills its MAC and IPv4 address into empty fields, **Use the interface's addresses** replaces them. The interfaces are listed when the page is first shown. Read with `GetIfEntry` and the address table the engine already used; compared with `Get-NetAdapter` on one computer. Linux and macOS read them with `getifaddrs`; that code is compiled and run only by CI (the loopback interface), it was not tried on a real Linux or macOS desktop.
- **Deleting old scans** (`history prune [--keep N] [--older-than 30d|DATE] [--dry-run]`, and `monitor --keep N`). Nothing ever deleted a saved scan, and a monitor saves 288 a day at the default interval. `history prune` deletes scans beyond the newest N of every target set and/or older than a window or date, with their research rows and alerts; `monitor --keep N` does it for its own targets after every cycle. The newest completed scan of every target set always stays; devices, identifiers and the baseline are kept. The file does not shrink, SQLite reuses the space. Not in the desktop yet.
- **Ctrl+C saves what was found.** On `scan`, `listen` and `dcp` the first Ctrl+C (or Ctrl+Break) cancels the run and saves the result as partial (exit status 2), as Q does in the `--tui` view; a second one ends the process at once. `monitor` ends cleanly, with the cycle in progress saved as partial. In the `--tui` view Ctrl+C is a stop key too. Before, Ctrl+C discarded a scan that had run for minutes. The handler is a few lines of platform code (`SetConsoleCtrlHandler`, `signal`), no new dependency. Checked by a unit test of the handler's decision and by a real Ctrl+C in a PowerShell terminal on Windows during a loopback scan (it printed the stopping line and saved the scan as partial); not tried on Linux or macOS.
- **SYN scanning of IPv6 targets** (`--syn`), on-link and routed, on Windows, Linux, macOS and the BSDs.
  - **On-link:** a link-local target is sent from a link-local address of the capture interface, a target inside the on-link prefix of one of its addresses from that address, both to the target's own MAC.
  - **Routed** (as for IPv4): the route comes from the OS (Windows `GetBestRoute2`, Linux `ip -6 route get`, macOS/BSD `route -n get -inet6`). It must leave through the capture interface. The frame goes to the gateway's MAC from a global or unique-local source of the target's kind, never a link-local one.
  - **MACs** come from the OS neighbour cache of that interface (Windows `GetIpNetTable2`, Linux `ip -6 neigh`, macOS/BSD `ndp -an`). Without an entry: one `ResolveIpNetEntry2` on Windows, else one UDP datagram to port 9 and a second look. The lookup is done once per next hop.
  - **No new setting:** the interface's IPv6 addresses are read when the engine starts (Windows by the interface that owns `--source-ip`, Linux `/proc/net/if_inet6` and macOS/BSD `ifconfig -a` by `--interface`). The capture filter adds them. A driver that refuses that filter gets the IPv4-only one, so IPv4 SYN is unaffected and IPv6 falls back.
  - **Fingerprint:** the SYN-ACK's hop limit is the TTL, with `df` 0.
  - **TCP connect instead,** with the usual note and before any frame is sent: no route, a route through another interface, no source address of the target's kind, our own addresses, or a missing MAC for the target or its gateway.
  - **Behaviour change:** with `--syn` and one interface, an IPv6 target the engine cannot reach now gets that per-port note; before, it was probed by connect silently. It keeps the adaptive connect timing.
  - **Not tested on a real network:** only synthetic frames and simulated link, routing and neighbour tables. The IPv6 capture filter has never been compiled by a real libpcap or Npcap, and the `GetBestRoute2` row offsets were not checked against a real route. The macOS/BSD path is type-checked on Windows but has never run.

  See [IPv6 targets](docs/src/scanning-engine.md#ipv6-targets).

### Changed

- **`help COMMAND` prints the help of that command** instead of the whole text, and `help NOSUCH` is an error (status 1). `-h` after a command is help; before, it was read as a target (`scan -h` said "Invalid start address", `search -h` searched for "-h").
- **All completion scripts** offer the export formats that were missing (`cyclonedx`, `tsv`, the `compliance-*` and sync formats) and complete file names for `--targets-file`, `--scope-file`, `--zones`, `--model`, `--record`, `--nvd`, `--csaf`, `--sboms`, `--vex` and `--on-alert`.
- The JSON of the kinds `changes`, `risk-score` and `alerts` may carry `truncated`, `total` and `scan_id` when it comes from the MCP server (additive, `v1` kept).
- **Inventory comparison with two pickers** (older scan A, newer scan B) instead of an "A" and a "B" radio button on every row.
- **The Finding column takes the room that is left** in the Findings table, so a wide window shows whole titles; the count and the hint above the table are one line that is cut short instead of two wrapped ones.
- **The Findings page gives the finding more room.** The grouping choice sits in the row of the filters and the two links of a row are the short words **Docs** and **Ref.** (read out as "Learn more" and "Reference"; the details panel keeps the full words). At 1100 px the Finding column is about 245 px wide instead of 150, and a small window shows one row more (five instead of four in German at 800×450).
- **A monitor uses feed data imported while it runs.** The KEV/EPSS, NVD, CSAF, VEX and SBOM caches are checked at the start of every cycle and read again when their file changed. A cache that is missing, half written or damaged at that moment keeps the data already loaded and does not count as a failed cycle. The user's own `cves.json` is still read once at start.
- **A host that accepts every port no longer costs unbounded work.** Above 100 open ports on one host (a captive portal, a proxy, a tarpit), services are identified on the first 100 only and no further provisional result is sent per port. The list of open ports stays complete, and the host carries a note that says so (`N open ports (a proxy or tarpit that accepts every connection?); services were identified on the first 100 only`). In the desktop's live view such a host stops gaining ports after 100 until it is finished.
- **`feeds import sbom` and `feeds import vex` never write over a file they could not load.** A cache that is damaged, of a newer version, or not a cache at all (a vendor document named with `--vex` or `--sboms`) stops the import with `nothing was imported and the file is unchanged`; before, it was replaced by the new import alone. A cache of an older version still starts over, and a cache larger than the program reads back is not written. The CSAF, KEV/EPSS and NVD imports still replace a cache they cannot read (they say so).
- **A mistyped `--db` is an error** for the commands that only read (`history`, `changes`, `alerts`, `diff`, `export`, `report`, `findings`, `devices`, `topology`, `ot-assets`, `search`, `segmentation`, `baseline show`, `research` except `schema`, `fingerprints` except `favicon`): `FILE: no such inventory`, status 1, and nothing is created. Before, it read as an empty inventory, and `alerts` created a new file at the mistyped path. Without `--db` a missing default inventory is still empty, and the commands that save still create the file.
- **`--dry-run` and `--keep` in the help of one command** say what they do for that command (`history --help`: what `history prune --dry-run` does, without the text about scans).
- **Remembered between starts**: the Addresses field (up to 2,000 characters), the sort of the hosts table, and the width of every table column that was dragged (hosts, findings, grouped findings, devices, OT assets; kept by column name, so switching an optional column off does not shift the others). The column that takes the rest of the width has none to remember. Checked across a restart in a real window.
- **Settings can be resized** and opens larger; the options that had no explanation have one on hover (the discovery options and every timing field).
- **Network map labels** move to the left of their node, below or above it when the place to the right is taken, and never cover another node; before, such a label was left out.
- **The message under the controls can be dismissed** (✕), and `Ctrl+F` on the Findings page takes its filter box instead of switching to Hosts.
- **About 35 messages that were English only are translated** (status and error lines, the scan summary, recording results, file dialog filters). Finding titles stay English: they come from the rules and name the documentation pages.
- **A monitor survives a cycle that fails.** One error in a cycle (the inventory locked by another program, an adapter down after standby, a host task that failed) used to end `monitor`, and the Windows service then stayed stopped. Now the error is printed, raised as a `monitor-cycle-failed` alert, and the next cycle runs; after five failed cycles in a row the monitor gives up, and a run with `--cycles N` in which a cycle failed exits with status 1. A cycle now reads everything its comparison needs before it saves the scan, and sends its alerts before it stores them and the devices, so a failure in between costs a stored copy or raises a new device once more, not an alert. The Windows service is installed with restart actions that also apply to an error exit (`SERVICE_CONFIG_FAILURE_ACTIONS_FLAG`; compiled, not installed in this change; services installed earlier need `service install` again).
- **Undelivered alerts are sent again.** What a webhook or syslog destination did not take (it was down, or the 30 s per cycle ran out) is kept, up to 1,000 alerts per destination, and sent first with the next cycle. Before, those alerts were dropped. The queue is also written to the inventory (a new table, schema version 7), so a monitor that is restarted sends what the last run could not deliver. It is kept per monitor (its targets) and per destination, by a hash of the destination and not its URL. A monitor that is killed between sending and writing sends those alerts a second time; alerts for a destination that is no longer configured are dropped.
- **The inventory waits 30 s for another program's write** instead of 3 s (the desktop app, a monitor and `research rebuild` on one database). Saving a large scan holds the lock for longer than 3 s, and the writer that gave up failed.
- **Shorter sidebar names** where a count would cut the name off: **Passive / OT** and **Inventory** (German: Passiv / OT, Inventar). The menus, the command palette and the hover text keep the full names. The host details button is **Timeline** without "…", since it opens a panel and not a dialog.
- **Host details in sections.** A summary (with the manufacturer), the host's findings with their links, the services per port, the host menu as buttons, and every identity field in a section that starts closed. The **Copy IP address** button and the **Actions** menu became the Actions section.
- A finding clicked on another page no longer clears the filter and search of the hosts table.
- **Sidebar and pages instead of floating windows.** A sidebar on the left lists the pages of the desktop (Overview, Hosts, Devices, Findings, Network map, Passive discovery / OT, Saved inventory) with a count next to each: hosts that answered, devices, findings in the colour of the worst one, passive observations, saved scans. Devices, Findings, the network map, passive discovery and the inventory were windows over the hosts table; now each is a full-size page, and wide tables scroll sideways. The filters and search of the hosts table moved onto the Hosts page.
- **Host details dock on the right** instead of opening as a window over the table. A click on a host, a finding, a device or a map node shows them there and keeps the page; **Close** or `Escape` closes them.
- **Desktop menus and controls reorganised.** The menu bar has five menus (File, Scan, View, Tools, Help) instead of two menus and eight buttons that looked the same. Menus, keyboard shortcuts and the command palette are built from one list of commands, so each entry is enabled under the same conditions everywhere. New shortcuts: `F5` start, `Shift+F5` stop, `Ctrl+O` import, `Ctrl+E` HTML report, `Ctrl+,` settings, `Ctrl+1` to `Ctrl+7` for the views and windows, `Ctrl+F` search, `F1` the shortcut list, `Ctrl+Q` quit; Up and Down choose a host in the table.
- **One preset control.** The Standard, Fast and Thorough buttons are gone: the Preset picker lists the presets and two adjustments, **Faster (turns Safe Mode off)** and **More thorough**. Full audit and Faster now ask **Turn Safe Mode off?** before they change anything (before, Fast turned Safe Mode off with one click).
- **More room for the hosts table.** The title row is gone, the status bar is one line, and the filters and search box are shown only with the Hosts view. Favorite addresses moved to a ★ menu next to the Addresses field. The default 800×450 window shows about two more table rows.
- **New logo.** The README logos (`assets/logo-*.svg`) and the social preview use the hexagon mark of the application icon instead of the radar.
- **Sidebar icons and the app logo.** Each page in the sidebar has a small line icon, painted in the text colour of the theme (no icon font, so the accessible names are just the page names). The logo and name sit at the top of the sidebar, and the counts are pills; the findings pill has the colour of the worst finding with black or white text, whichever reads better. The sidebar is 196 points wide so that the longest German page names fit, and scrolls when the window is too short for it. The empty Overview and Hosts pages show the logo when the window is tall enough. A sidebar entry opens its page with Enter when it has the keyboard focus (click test).
- **Calmer hosts table.** The Status column shows a coloured dot and the status in the normal text colour instead of a column of green words. The open ports take the remaining width, so no gap opens between Hostname and Open TCP ports; with optional columns on, the host name gives way instead. The default widths fit the 800×450 window in German.
- **Hosts and Devices are one page.** The Hosts page has two modes, **By address** (the scan results with status and ping) and **By device** (addresses with the same MAC merged, with devices only seen passively; it was the Devices page), switched by the first two buttons of its filter row. The sidebar has six entries instead of seven; `Ctrl+3`, the View menu and the command palette still open the device mode, and `Ctrl+F` there focuses its filter box.
- **The findings of a large scan are worked out in the background.** Above 4,096 hosts and observations the sidebar's findings count (and the Risk column) used to appear only once the Findings page had been opened; now a thread of its own works them out once the scan or capture has finished, and the count appears without stalling the window. An answer for data that changed meanwhile is dropped; one for hosts that were only sorted is kept.
- **The device timeline is a panel under the page** instead of a window over it: it spans the page beside the host details, can be made taller by dragging its edge (up to half of the window) and has its own **Close**. Everything under its header scrolls together.
- **The Risk column of the hosts table can be sorted**: the host with the worst finding first, hosts without findings last. Sorting works the findings out if they were not yet (a large scan), and sorting no longer makes the app work out findings and host names again.
- **Whole-row clicks in the hosts table.** A click or right click anywhere in a row selects the host or opens its menu, not only on the address.
- **Settings in sections.** The window is called Settings and is grouped into collapsible sections (Safe Mode and discovery, Services and identification, Industrial (OT), SNMP, Traceroute, Timing and performance, Scripts, rules and recording, Appearance and language, Scheduled scans, Updates). **Tools → Scheduled scans…** opens it at the schedule.

### Fixed

- **Nothing the desktop copied reached the system clipboard.** The clipboard support of the GUI library was never compiled in, so every copy (the host menu's **Copy IP address**, the copy entries of the tables, `Ctrl+C` in a field) stayed inside the window; pasting what was copied elsewhere goes the same way and presumably failed too. Found by trying the copy menu in a real window. The build now includes it (the `arboard` crate; on Linux also the Wayland clipboard crates, six new entries in `Cargo.lock`). Copying was tried on Windows; pasting, Linux and macOS were not.
- **`findings ID --top N --fail-on-findings` counted findings a vendor statement had cleared**; the list without `--top` did not.
- **An unknown scan ID printed `Query returned no rows`.** It now says `No scan with ID N; see "history"`, and `export ID --format xyz` names the unknown format first.
- **More desktop messages that were English only are translated**: eight that a search for text outside the translation macro found (import errors, the scope file error, two file dialog filters, the reasons a wire capture was not made). The search is a heuristic, so single words may remain.

### Changed

- **Faster host discovery in `--fast`**: the pool for blocking OS calls (ICMP echo, the ARP check, route lookups) now has 512 slots, matching the runtime's blocking threads, instead of 256. On a /24 every address waits on these calls at once. Home /24 on Windows with 2 ports, 3 interleaved runs each: 8.0–10.2 s before, 5.8–6.3 s now, with the same open ports and unused addresses. Safe Mode runs 8 hosts at a time and is unaffected.
- **Unused addresses on the local network: Linux too.** On Linux the verdict comes from the kernel's own ARP for the first port probes, so no packet is added. When a host has answered nothing 3.5 s after its first probe, and its neighbor entry still has no MAC on a direct route through an ARP interface, the waiting probes are stopped. The other ports, UDP and the BACnet Who-Is are then skipped, with a note. Hosts with a MAC (live or cached), routed, IPv6, the SYN engine and `--tcp-only` are unchanged. A host that rejects with ICMP host-prohibited (firewalld's default; also reported as "no route to host") is still probed in full. On GitHub's Linux runner, against its Docker bridge: one unused address takes 3.6 s instead of 12.3 s. A CI step (`lab/neighbor_check.py`) checks four cases on every run: unused, live, host-prohibited and just-stopped containers. The desktop shows such a host as "Unused", even when it also has the unprivileged-ICMP note. Not tried on a physical LAN or Wi-Fi; macOS is unchanged.

- **Adaptive TCP connect timing is on by default** for hosts without a ping RTT (hosts that drop ping, `--tcp-only`, ping adaptation off); a host that answers ping keeps its ping-based timeout and is probed exactly as before. `--no-adaptive-tcp` or the new desktop setting turns it off; `--adaptive-tcp` is still accepted. Before, a host that drops ping waited the full port timeout and a retry on every silent port. Home LAN (Windows, top 100 ports, `--fast`, 10 interleaved rounds): the answering devices took 6.7–6.9 s instead of 17.7–19.3 s whenever a slow power-saving device was absent, with the same open ports in all runs. The documented Windows drawback (closed ports shown as unanswered) dated from before probe sockets stopped retransmitting the SYN. The desktop switches its saved preferences over once (they held an "off" that nobody chose, since there was no checkbox); turning it off afterwards is kept. Scheduled or service scans and saved scans keep their stored value, which is off; new command-line and MCP scans get it.

- **Exit status 2 for partial results.** `scan`, `listen` and `dcp` now exit with 2 (was 1) when they saved a partial result after an error, and `scan` exits with 2 (was 0) when it was stopped early in the `--tui` view (Q/Esc) and saved a partial scan. - **OT read-only guarantee is now a type-level property** (ROADMAP H51, partly): all active OT requests (Modbus Read Device Identification, S7 setup and SZL reads, EtherNet/IP List Identity, BACnet Who-Is, OPC UA discovery) are built from allow-list enums in `ot::readonly` and sent only through socket wrappers that accept nothing but those request types, so a write or control function code cannot be sent without adding an enum variant. - OCSF findings without a CVE are Detection Findings (class 2004) instead of Vulnerability Findings (2002).

- **A scan held one record per probe in memory**: each host kept the result of every port until it finished, and with `--fast` every host of a /24 runs at once. Closed and unanswered ports without a note are now counted as they finish. Loopback /24 on Windows, same results: 1,000 ports 59.8 → 33.3 MB peak, 4,000 ports 155.7 → 46.0 MB; run time unchanged.
- **Peak memory of small tools in the speed comparison was the harness's own size**: on Linux, `ru_maxrss` from `wait4` keeps the high-water mark of the Python process the tool was forked from, so nmap and Network Scope both showed 28.2 MB. `lab/speed_compare.py` now measures through GNU time, and reports n/a without it.

### Removed

- **JA4S and JA4X** (`tls.<port>.ja4s`, `tls.<port>.ja4x`, the `ja4x` research kinds): the FoxIO License 1.1 that covers JA4+ does not permit monetization and conflicts with the MIT licence. JA3S, JARM, HASSH and the public-key hash are used instead.

### Tested on a real network

- 2026-11-20, a home LAN, Windows 11 with Npcap, not elevated: Safe Mode and on-link SYN scans of a /24, the ARP sweep, TCP traceroute, `listen` and live OT capture, DCP Identify, one scan over two interfaces (Ethernet and a VMware adapter), `--ipv6-discover` against real neighbours, the MCP `scan` tool on the /24 (336 s with 5 ports, so expect a partial result at the default 50 s limit) and the GUI's Scan my network detection. Not covered: SYN and traceroute to routed targets, Linux and macOS.

## [0.5.0] - 2026-11-19

First public release. The [documentation](https://sparkz400.github.io/network-scope/) describes current behaviour; this entry lists what changed since 0.4 and what has not been verified.

### Added

- **Console binary** `network-scope-cli` (Windows console subsystem; shells wait, exit codes work), installed and put on PATH by the installer, built by CI.
- **SYN to routed IPv4 targets** via the gateway MAC (OS routing table).
- **`--adaptive-syn`**: RFC 6298 per-target reply windows and an AIMD congestion window.
- **`--arp-sweep`**: ARP who-has sweep through the capture handle.
- **Traceroute methods** `--trace-method icmp|tcp|udp`, `--trace-port N`; ICMPv6 traceroute; `trace --fast --trace-method`.
- **SMB** 3.1.1 negotiate contexts and NTLM challenge (dialect, GUID, encryption, compression, signing, clock skew, OS build, NetBIOS/DNS names); findings `smb-no-encryption`, CVE-2020-0796 hint. The NTLM SESSION_SETUP is not sent in Safe Mode.
- **TLS 1.3 suite enumeration** (not in Safe Mode), **JA4S-style fingerprint** (`tls.<port>.ja4s`), **HASSHServer** (`ssh.<port>.hassh`).
- **CVE rules in `data/cves.json`**, user override file and `--cves FILE`; CPE names (`svc.<port>.cpe`).
- **UDP payload probes** from probes.json (`"proto": "udp"`): SQL Server Browser, rpcbind, memcached, SIP. `probes` lists UDP probes too; `--probes` applies to UDP-only scans.
- **OS evidence** from the SMB NTLM version, Dropbear, Cisco/MikroTik SSH.
- **Diff** `--format lines|json|text` with new/resolved/unconfirmed findings and `--ignore`.
- **`devices --history MAC|IP`** timeline across saved scans.
- **Exports** `md` and `jsonl`; report findings-by-host table, new/resolved findings vs. baseline, CPE column. GUI: Markdown export.
- **nmap XML** product-name mapping both ways, CPE, Windows OpenSSH handling.
- **Monitor alert sinks** `--webhook` (http only), `--syslog` (UDP/TCP, RFC 5424), `--alert-timeout`; de-duplication across cycles (`--no-dedup`, `--renotify-hours`); `--quiet` silences monitor progress; `--report-missing` hint.
- **pcap link types** Linux SLL/SLL2 and raw IP; **ingest progress** (`ot-listen --progress`, GUI progress bar and Cancel).
- **OT TCP reassembly** for Modbus, S7, IEC 104, EtherNet/IP, OPC UA (`--no-reassembly`).
- **GUI**: OT passive section (pcap/live, asset table, exports, saved to inventory, saved as partial on close, refilled when reopened); sortable/filterable Findings and Devices; script dry-run; background exports; Settings for ARP sweep, adaptive SYN, trace method/port (off in Safe Mode); Clear results and captures; debounced preference saving.
- **TUI** row selection, host details, sort; **shell completions** (`completions powershell|bash`), global `--quiet`.
- **Device identity**: routed hosts with the same SMB GUID and NetBIOS name merge; SMB names become host names; CPE/HASSH/JA4S values are not device-type evidence.
- **UDP scan** never sends to OT or printer ports (skipped with a host note).
- **Diff noise**: `*.clock_skew` and `*.boot_time` are volatile like `*.days_left`.
- **Repository**: documentation book (`docs/`), community health files, issue templates, release and documentation workflows, data provenance (`data/README.md`), third-party notices.

### Changed

- Rust edition 2024 (toolchain pinned to 1.100.0); ratatui 0.30 and crossterm 0.29.
- First scan after upgrading: `tls.<port>.ciphers` gains a `TLS1.3:` part on TLS 1.3 servers, and nmap imports stored by 0.4 differ in `svc.<port>.product` spelling; both show as identity changes once.
- A diff of an old /23-or-larger snapshot against a new one can list inner .0/.255 addresses as new devices.
- OT passive `packets` counts messages, not segments, on the reassembled ports.
- Routed hosts merged by SMB GUID + NetBIOS name keep the device id of the lowest address; an existing monitor database may raise one `new-device` or `device-missing` alert for such hosts after the upgrade.
- On Linux a rescan may report a host found earlier only through a now-STALE ARP entry as not responding.
- Monitor: `device-missing` is Low, `address-changed` Medium; new `capture-incomplete` (Low).
- 2222/tcp is listen-only (SSH greeting → SSH exchange, else industrial). Printer ports 9100-9107 and 515 get a passive banner wait only.
- Scripts: 250 ms wall limit per host across all scripts; Rhai `sleep()` disabled.
- `CREDITS.md` is now `THIRD-PARTY-NOTICES.md`.

### Fixed

**Engine**

- `--syn --rate N`: one rate token per transmitted SYN (retransmits included), taken by the SYN I/O thread only; a probe's reply window starts when it is sent, so queued probes are never reported unanswered. Retransmits go first and double the wait up to the port timeout.
- SYN capture is non-promiscuous with the BPF filter `tcp and dst host <source-ip>`; SYN probes share the global 4,096 in-flight bound. After Stop, probes whose caller went away are dropped before a token is taken.
- The global socket permit is taken before a probe task is spawned (large `--workers` × `--parallel` no longer park millions of tasks). Blocking slots are held until the native call really ends.
- Stop keeps hosts that had already finished.
- OT identification runs for hosts that responded to something and, when nonresponders are scanned, for silent hosts, which then get only the single BACnet Who-Is (wait capped at 2 s). Devices that answer only BACnet/IP are still found.
- "Skip .0 and .255": CIDR blocks skip only their own network and broadcast address; /31 and /32 are never trimmed; dash ranges keep the old rule.
- CSV exports neutralise formula-leading cells (`=`, `+`, `-`, `@`, TAB, CR) with `'`.
- libpcap library names on macOS/Linux; MAC lookup skipped for routed IPv4 targets on Linux; a cached Linux neighbor entry counts as alive only if REACHABLE or new after the poke; the miss path is one poke and one 250 ms wait.
- Traceroute replies are matched by a per-trace ICMP id and the quoted destination; echo matching checks the sequence (and the id where the OS keeps it).
- Windows: the GUI binary attaches to the parent console whenever it has none and rebinds only unusable std handles, so stderr is no longer lost when only stdout is redirected.

**Services / TLS / risk**

- SMBv1 detected with a separate SMB1 negotiate; smb1 and signing reported independently.
- RDP: a second connection tests whether NLA is actually required.
- LDAP anonymous-bind finding needs resultCode 0.
- TLS: weak-first per-version budget (`suites_truncated`), `not_yet_valid` (+ finding), `cert_error`, self-signed also requires AKI == SKI.
- OpenSSH CVE-2018-15473 range fixed (7.7p1 now matched). PHP end of life is date-aware.
- HTTP Host header carries `:port` for non-80/443 ports and brackets IPv6.

**Passive / OT / monitor**

- A capture error or the observation cap no longer ends `monitor`. New-device alerts treat 2222/tcp as OT (High).
- DHCP observations keep the client in `ip`/`mac` and record servers per `dhcp_server.<ip>`.
- Capture thread tolerates transient read errors; a full queue reports one non-fatal error. `listen`/`dcp` treat error items as warnings and keep collecting.
- BACnet wait clamped to 200-2000 ms; port unreachable means "no BACnet".
- CIP object-specific services decoded by path; Unconnected Send / Multiple Service Packet unwrapped.
- Requests to broadcast/multicast destinations record only the client.
- pcapng `if_tsresol`, oversized blocks skipped, classic pcap FCS stripping and link-type masking.

**CLI / GUI**

- `scan`, `listen`, `dcp` save partial results on errors and exit 1. TUI stops on `q`, `Q`, Esc.
- Exports carry the real scan time (stored time for saved/reopened scans, current time for live GUI results) instead of "time not recorded".
- GUI: the OT pcap import now flushes partially reassembled messages; a cancelled import is partial, not an error.

- **Npcap was never loaded on Windows:** the driver path used forward slashes, which `LoadLibraryExW` rejects with `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR`, so SYN scanning, the ARP sweep, TCP traceroute, `listen`, DCP and live OT capture always reported "Capture driver unavailable" even with Npcap installed. Found in the first real-hardware test.

### Security

- **Bundled SQLite 3.54.1** (rusqlite 0.41): fixes RUSTSEC-2026-0459 / CVE-2026-119375, where a crafted database and `-wal` file pair could make queries return uninitialised memory. Only inventory files from an untrusted source were exposed.
- Checks in CI: `cargo deny` (advisories, licenses, sources) and `cargo audit` on every change and weekly, and a gitleaks secret scan of the full history on every push; CodeQL static analysis; every GitHub Action pinned to a commit SHA. Release files carry signed build provenance (`gh attestation verify`), and the Sigstore bundle is attached to the release.
- `osv-scanner.toml` lists the six transitive "unmaintained" advisories (no vulnerabilities) with a reason and an expiry date for review.

### Not done

Deliberately, or for lack of a test setup:

- JARM: needs byte-exact hellos to match public databases and too many connections for Safe Mode.
- x509 signature verification for self-signed detection (would need the `verify` feature of x509-parser).
- `store::list_alerts_since` (exact alert de-duplication restore with several monitors on one database).
- A GUI field for a CVE rules file (the user file in LOCALAPPDATA and `--cves` cover it).
- HTTPS webhooks (no bundled CA store).

### Untested

- Npcap/libpcap features not yet run on a real interface: SYN to routed targets, ARP sweep, TCP traceroute, live OT capture, DCP; libpcap on Linux/macOS. (Verified on Windows with Npcap: on-link SYN, passive `listen`; see the lab and testing page.)
- UDP traceroute with administrator/root rights; ICMPv6 hop-limit expiry from a real router on Windows.
- Linux/macOS glue (`next_hop`, neighbor states, raw ICMP/ICMPv6, UDP hop): not compiled on the development machine; CI is the first compile.
- The GUI binary's console attach when started from a shell; the installer script (never compiled with `iscc`); the CI, release and documentation workflows.
- Webhook/syslog delivery against real receivers; SMB against Samba; TLS 1.3 enumeration against OpenSSL/Schannel; JA4S against the reference implementation; CPE names against the NVD dictionary.
- OT decoders and reassembly against real industrial traffic (synthetic frames only).
